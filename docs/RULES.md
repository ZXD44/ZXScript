เอกสารนี้ระบุกฎเหล็กและข้อกำหนดที่ **AI Agent และนักพัฒนาทุกคนต้องปฏิบัติตามอย่างเคร่งครัด** เมื่อใช้งานหรือพัฒนาต่อยอด ZXScript เพื่อความปลอดภัยสูงสุด ประหยัด Token ป้องกันการถูกระงับบัญชี และรักษาคุณภาพโค้ดระดับ Production

---

## 1. กฎความปลอดภัยและการป้องกันการระงับบัญชี (Anti-Ban & Safety)

### 1.1 การแบ่งงานออกเป็นระบบย่อย (Sub-System Modularity)
- ห้ามสั่งให้ AI พัฒนาเกมทั้งเกมในคำสั่งเดียว เพราะจะทำให้เกิดการเรียกคำสั่งวนซ้ำต่อเนื่องจนติด Rate Limit
- บังคับแบ่งงานออกเป็นระบบย่อยทีละ 1 ระบบ และรอรับผลลัพธ์เพื่อตรวจสอบความถูกต้องก่อนเริ่มระบบถัดไป

### 1.2 การหน่วงเวลาเลียนแบบมนุษย์ (Humanized Delay Jitter)
- ระบบส่งข้อความจะหน่วงเวลาสุ่ม `1000 - 2200ms` ก่อนส่งผลลัพธ์กลับไปยังโมเดล AI
- ห้ามปิดหรือบายพาสฟังก์ชันหน่วงเวลานี้เด็ดขาด เพื่อป้องกันการตรวจจับจากระบบคลาวด์

### 1.3 การกู้คืนการทำงานผ่าน ChangeHistoryService
- ทุกคำสั่งปรับแต่งเกมผ่าน Luau ต้องถูกห่อหุ้มด้วย `ChangeHistoryService:SetWaypoint()`
- หากโค้ดทำงานผิดพลาด ต้องสามารถย้อนกลับสถานะ (Undo) ใน Roblox Studio ได้ทันทีผ่านปุ่ม `Ctrl + Z`

## 2. กฎการจัดระเบียบโครงสร้างโค้ด (Clean Architecture & Modular Design)

### 2.1 ขีดจำกัดความยาวของไฟล์โค้ด (Line Limit Rule)
- ทุกไฟล์ในโปรเจกต์ (ทั้ง Python, JavaScript, CSS, HTML) ต้องมีความยาว **ไม่เกิน 500 - 600 บรรทัด**
- หากไฟล์ใดเริ่มมีความยาวเกิน 500 บรรทัด ต้องแตกออกเป็นโมดูลย่อยตามหน้าที่รับผิดชอบ (Separation of Concerns) ทันที

### 2.2 การแยกค่าคงที่และการตั้งค่า (Configuration & Constants)
- ห้ามฝัง Magic Numbers หรือ Magic Strings ภายในโค้ดการทำงานหลัก
- ดึงค่าคงที่ทั้งหมดไปไว้ในไฟล์เฉพาะ เช่น `constants.py` หรือ `constants.js`
- ค่าการตั้งค่าที่แก้ไขได้ต้องผ่านไฟล์ `config.json` หรือ Chrome Storage

### 2.3 การทำงานแบบเบื้องหลัง (Headless Execution)
- โปรแกรม Bridge และ Native Messaging Host ต้องทำงานแบบซ่อนหน้าต่าง (`CREATE_NO_WINDOW`)
- ห้ามสร้างหน้าต่าง CMD เด้งขึ้นมารบกวนการทำงานของผู้ใช้
- สตรีมข้อความ Log สดผ่าน IPC ไปยังหน้าต่างส่วนขยายหรืออินเทอร์เฟซในหน้าเว็บเท่านั้น

## 3. มาตรฐานการเขียนโค้ด Luau สำหรับ Roblox Studio (Engine 0.744+)

### 3.1 บังคับใช้ Modern Task Library
- ห้ามใช้คำสั่งเก่าที่ยกเลิกแล้ว ได้แก่ `wait()`, `spawn()`, `delay()` เด็ดขาด
- บังคับใช้ `task.wait()`, `task.spawn()`, `task.delay()`, `task.cancel()` เสมอ

### 3.2 สถาปัตยกรรมแยก Server และ Client
- โค้ดที่ประมวลผลข้อมูลและ Logic สำคัญต้องอยู่บน Server (`ServerScriptService`) 100%
- Client (`StarterPlayerScripts`) มีหน้าที่รับคำสั่งจากผู้ใช้และเรนเดอร์อินเทอร์เฟซเท่านั้น
- ห้ามเชื่อถือข้อมูลดาเมจจาก Client โดยเด็ดขาด ต้องตรวจสอบระยะ Line-of-sight และ Cooldown บน Server เสมอ

### 3.3 การจัดการข้อมูลผู้เล่นที่ปลอดภัย
- บันทึกข้อมูลด้วย ProfileStore หรือ DataStoreService
- ต้องมีระบบ Session Locking เพื่อป้องกันการ Dup ไอเทม
- ต้องเชื่อมต่อ `game:BindToClose()` เพื่อเซฟข้อมูลผู้เล่นทุกคนก่อนเซิร์ฟเวอร์ปิดตัวลง

## 4. มาตรฐานส่วนติดต่อผู้ใช้ (Impeccable Style Standards)

- ออกแบบตามหลัก Minimalism เรียบง่าย สวยงาม ไม่ซับซ้อน
- ลดการใช้อนิเมชันที่ทำให้เครื่องแลค รันที่ระดับ 60fps ลื่นไหล
- ตัดอีโมจิออกจากปุ่มกดและข้อความสถานะ เพื่อความกระชับและเป็นมืออาชีพ
- ใช้โทนสี Dark Neutral (Zinc-950) และแถบ Scrollbar ขนาดบาง 5px

### 4.1 ข้อกำหนดด้านคำและข้อความใน UI (User Wording Preference)
- **ห้ามใช้คำว่า "Bridge" ใน UI และข้อความแจ้งเตือนทั้งหมดอย่างเด็ดขาด** (ผู้ใช้ระบุไม่ชอบคำนี้)
- ให้ใช้คำว่า **"Studio"**, **"ระบบเชื่อมต่อ"**, หรือ **"การเชื่อมต่อ"** แทนในทุกจุด เช่น "เชื่อมต่อ Roblox Studio", "เปิดการเชื่อมต่อ", "เชื่อมต่อสำเร็จ"
- แถบ Action Bar ในหน้าเว็บต้องกระชับ ไม่ยาวเกินไป พร้อมรองรับ Responsive บนทุกขนาดหน้าจอ
- นำรูปไอคอนเว็บทรงโลกออก และใส่เครดิตผู้พัฒนาเป็น **"ZXD44"** สไตล์มินิมอลตามธีม UI
